Sitio Web ISeP Santa Fe — Instituto de Seguridad Pública

1. Visión general

Sitio web institucional del Instituto de Seguridad Pública (ISeP) de la Provincia de Santa Fe. SPA construida con React 19 + Vite 8 + React Router 7. 100% responsive (móvil, tablet, desktop). Lazy loading por ruta para tiempos de carga optimizados.

17. Disponibilidad

npm install → npm run dev (localhost:5173). Build: npm run build → npm run preview. Lint: npm run lint. Tests: npm run test.

17.1 Testing automatizado

Suite de tests con Vitest + React Testing Library + jsdom:

  • 18 tests en 3 archivos, cubriendo la capa de datos (no los componentes UI)
  • datos.test.js: valida estructura de noticias (IDs únicos, campos requeridos, categorías válidas, imágenes admisibles como null)
  • institucional.test.js: valida estructura de escuelas, carreras, cursos y convocatorias
  • buscador.test.js: valida funcionalidad de búsqueda y resultados agrupados
  • Tests ejecutados automáticamente en CI (GitHub Actions) en cada push
  • Ejecutar localmente con npm run test

17.2 CI/CD

GitHub Actions ejecuta en cada push:

  • Lint → Build → Test
  • Si cualquier paso falla, el push se bloquea

18. Publicación de noticias — Guía paso a paso

18.1 Estructura de datos

{
  id: 12,
  titulo: "Título de la noticia",
  categoria: "Institucional",
  fecha: "3 DE SEPTIEMBRE, 2026",
  fechaCorta: "3 SEP",
  excerpt: "Extracto breve...",
  img: "https://picsum.photos/seed/n12/900/500",  // o null
  adjuntos: [
    { nombre: "Resolución 123.pdf", url: "/docs/resolucion-123.pdf" }
  ],
  escuelas: ["policia", "superior", "especialidades", "investigaciones", "ead"],
  contenido: `Primer párrafo.\n\nSegundo párrafo.`
}
Campo img: puede ser una URL de imagen (local o externa) o null. Si es null, se muestra un placeholder con ícono de material symbols en lugar de la imagen. Esto permite publicar noticias sin foto alusiva.
Campo contenido: si se define, se usa como cuerpo de la noticia en el detalle. Si no se define, se genera un texto genérico a partir del título y excerpt.
Campo adjuntos: array opcional de objetos { nombre, url }. Cada adjunto se renderiza como botón de descarga en el detalle de la noticia. El campo nombre es el texto visible del botón y url es la ruta relativa (desde public/) o URL absoluta del archivo.
Campo escuelas: array de IDs de escuelas asociadas a la noticia. Valores válidos: "policia", "superior", "especialidades", "investigaciones", "ead". En /noticias se muestran todas las noticias sin importar este campo.

18.2 Pasos para publicar

  1. Preparar imagen alusiva (4 opciones):
    • Opción A (recomendada): Imagen local en public/img/noticias/
    • Opción B: URL externa
    • Opción C: Placeholder con picsum.photos — https://picsum.photos/seed/mi-noticia/900/500
    • Opción D: Sin imagen — img: null (se muestra placeholder con ícono)
    900×500 px (16:9), JPG/PNG, <200 KB.
  2. Definir categoría: Institucional | Académica | Escuelas | Eventos | Convenios.
  3. Colocar archivos adjuntos en public/docs/: colocar los archivos (PDF, DOC, etc.) que se quieran adjuntar a la noticia en la carpeta public/docs/. Si no hay adjuntos, omitir este paso.
  4. Agregar en src/data/noticias.js: nuevo objeto al array con id único y campo escuelas para asociar la noticia a escuelas específicas. Ejemplo: 
    {
  id: 14,
  titulo: "Título descriptivo",
  categoria: "Institucional",
  fecha: "4 DE SEPTIEMBRE, 2026",
  fechaCorta: "4 SEP",
  excerpt: "Extracto de 1 a 2 oraciones.",
  img: "/img/noticias/mi-imagen.jpg",
  adjuntos: [
    { nombre: "Resolución adjunta.pdf", url: "/docs/resolucion.pdf" }
  ],
  escuelas: ["policia"],
  contenido: `Primer párrafo del cuerpo.

Segundo párrafo con más detalle.`,
}
  5. Verificar el buscador: src/data/buscador.js importa directamente de noticias.js, por lo que la noticia aparecerá automáticamente en las búsquedas. No es necesario agregar nada manualmente.
  6. Probar: npm run dev, verificar en home, /noticias y detalle. Al hacer clic en la card, se abre el detalle con imagen, contenido (campo contenido si existe, o texto generado), botones de descarga de adjuntos y noticias relacionadas.
  7. Confirmar: npm run build + npm run lint.

18.3 Documentos adjuntos y links

  1. Subir documento a public/docs/ o usar URL externa.
  2. Agregar campo adjuntos al objeto: [{ nombre, url }].
  3. Modificar NoticiaDetalle.jsx para renderizar la sección de adjuntos.

19.3 Sitemap.xml

  • Incluye: Home, 5 escuelas, noticias, normativa, biblioteca, ingreso, institucional, secretaría.

  • Disponible en /sitemap.xml.

19.4 Google Analytics 4

  • Herramienta: gtag.js (Google Analytics 4).
  • Carga: asíncrona, no bloquea el render.
  • Modo: solo producción (desactivado en npm run dev).
  • ID configurable: en src/components/Analytics.jsx (variable GA_ID) y src/utils/analytics.js.
  • Estado actual: el ID es un placeholder (G-XXXXXXXXXX). En desarrollo, Analytics retorna null. En producción, gtag.js se carga pero con el ID placeholder no se recolectan datos reales.
  • Para activar: reemplazar el ID placeholder con un Measurement ID real de GA4 en ambos archivos. Ver guía paso a paso en funcional.md.

19.5 PWA

  • manifest.json: configuración de Progressive Web App (nombre, colores, iconos).
  • robots.txt: permisos para crawlers (allow: /, Disallow: /api/).
  • Permite instalar el sitio como app en móviles y escritorio.

19.7 Error Handling

  • ErrorBoundary global: captura errores de render en cualquier componente y muestra una pantalla amigable en lugar de pantalla blanca.
  • NotFound (404): página dedicada para rutas inexistentes con enlace de retorno al inicio.
  • Ambos implementados en App.jsx como wrappers del router.
